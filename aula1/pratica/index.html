Casos de Teste e Critérios de Aceitação

O que é um Caso de Teste?

Um caso de teste é um documento que descreve uma situação específica a ser verificada no sistema. Ele define o que testar, como testar e qual resultado é esperado.

Um bom caso de teste deve conter:

  • ID: Identificador único e rastreável (ex: CT-Cadastro-001)
  • Cenário/Descrição: O que está sendo testado, em linguagem clara
  • Pré-condição: Estado do sistema antes da execução do teste
  • Dados de entrada (Entrada): Valores ou ações que o testador vai fornecer/executar
  • Resultado esperado: O que deve acontecer se o sistema estiver correto
  • Resultado obtido: Preenchido após a execução (passou ou falhou)

Como Criar Casos de Teste?

Siga estas etapas para derivar casos de teste a partir de um caso de uso:

  1. Entenda o fluxo principal: Qual é o caminho feliz? (usuário faz tudo certo)
  2. Identifique alternativas: O que acontece com entradas inválidas, dados faltantes, limites?
  3. Pense nas exceções: O que o sistema faz quando algo dá errado? (conexao, permissao, etc.)
  4. Defina dados de teste concretos: Use valores reais, não genéricos ("email@email.com", nao "um email")
  5. Escreva o resultado esperado de forma objetiva: "Mensagem de erro X é exibida", nao "deve dar erro"

O que são Critérios de Aceitação?

Critérios de aceitação são condições que devem ser satisfeitas para que uma funcionalidade seja considerada pronta e aceita. Eles traduzem os requisitos em cenários testáveis usando o formato DADO / QUANDO / ENTÃO (Given / When / Then).

Diferença entre caso de teste e critério de aceitação:

  • Caso de teste: Foca em verificar se o código funciona (perspectiva do tester)
  • Critério de aceitação: Foca em confirmar que o requisito foi atendido (perspectiva do produto/cliente)

Exemplo de critério de aceitação no formato DADO/QUANDO/ENTÃO:

CA-Cadastro-001: Cadastro com sucesso

DADO que o usuário está na tela de cadastro

QUANDO preenche nome, email válido e senha com mínimo 6 caracteres

ENTÃO a conta é criada e o usuário é redirecionado para o painel

Dicas para uma Boa Especificação

  • Seja específico: Evite termos vagos como "rápido", "bonito", "funcionar"
  • Use dados concretos: Em vez de "email inválido", escreva "email sem @: 'abc'"
  • Um critério = uma afirmação: Não misture múltiplas condições num único critério
  • Priorize o caminho feliz: Comece pelo fluxo principal, depois cubra exceções
  • Revisite os requisitos: Cada requisito funcional deve ter pelo menos um critério de aceitação
Caso de Uso

StreamTogether — Assistir com a Galera

O StreamTogether é uma plataforma de streaming que permite aos usuários assistir vídeos, séries e filmes sincronizados com amigos em tempo real. Diferente de plataformas tradicionais, o foco é a experiência social: criar sessões compartilhadas ("watch parties"), interagir via chat ao vivo e enviar reações enquanto assistem juntos, mesmo estando em locais diferentes.

10 Casos de Uso do Sistema

UC-01
Criar Conta
O usuário se cadastra com nome, email e senha para acessar a plataforma.
UC-02
Fazer Login
O usuário entra no sistema com email e senha cadastrados.
UC-03
Criar Sessão de Watch Party
O host cria uma sessão, seleciona o conteúdo e define um nome para a sessão.
UC-04
Entrar numa Sessão
O convidado entra numa sessão existente usando link ou código de convite.
UC-05
Sincronizar Playback
O vídeo é sincronizado automaticamente entre todos os participantes da sessão.
UC-06
Controle do Host (Play/Pause)
Apenas o host pode pausar, dar play ou retroceder o vídeo para todos.
UC-07
Chat ao Vivo
Participantes enviam mensagens de texto durante a sessão em tempo real.
UC-08
Reações (Emojis)
Participantes enviam emojis que aparecem flutuando na tela para todos.
UC-09
Sair da Sessão
Um participante pode sair da sessão a qualquer momento.
UC-10
Encerrar Sessão (Host)
O host encerra a watch party, desconectando todos os participantes.
